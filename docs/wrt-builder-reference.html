Справочник прошивки

Universal WRT Builder

Конвейер GitHub Actions, который собирает прошивку OpenWrt / ImmortalWrt под несколько устройств в выбранном «варианте» начинки, и скрипт zz1-final-offline-setup.sh, который доводит роутер до рабочего состояния на первом старте. Эта страница объясняет, что задаётся при запуске, что происходит во время сборки, чем отличаются варианты и что получается после прошивки.

Фиды из репозитория пакетов feeds_latest
данет
 нет

Фиды packages, luci, routing, telephony, video берутся не на коммитах релизного тега, а на тех, из которых собран репозиторий пакетов ветки (releases/packages-<ветка>/<arch>/feeds.conf на downloads.openwrt.org или downloads.immortalwrt.org). Прошивка получается такой же, как релиз после apk upgrade, и обновлений после прошивки почти нет. Ядро, kmods и хеш ядра остаются от релиза. Коммит заменяется, только если он есть на GitHub и новее закреплённого: если тег новее сборки пакетов (так бывает у ImmortalWrt), фид остаётся как в теге. Свои фиды (part1, podkop, forkop, passwall…) не трогаются. Для master не действует. В combo поле формы игнорируется: значение задаётся для каждой сборки полем feeds матрицы (по умолчанию везде «да»). Учтите: sing-box в фиде может стать новее (25.12: 1.12 в теге → 1.13 в репозитории) — homeproxy без патчей тогда остановится на проверке совместимости. В имени артефакта — feeds-repo или feeds-tag, в имени сборки в Actions и в Telegram — feeds:repo / feeds:tag. В прошивке — /etc/build_feeds и пометка feeds: … в баннере. Файл пишется после feeds update: первая строка repo, только если коммит хотя бы одного фида действительно заменён (иначе tag, даже при включённом поле — например, когда тег новее сборки пакетов), дальше строки feeds.conf всех фидов с коммитами, которые реально скачаны (у фидов на ветке — её голова на момент сборки). Файл годится как feeds.conf для повторной сборки на тех же исходниках.

◆

combo и all — особый случай. Режим combo игнорирует поля Build Variant, AdGuard Home, sing-box, youtubeUnblock, Скрипт zz1, Применять патчи и Фиды из репозитория пакетов: три сборки и их настройки жёстко зашиты в job setup (таблица ниже). Режим all собирает все шесть устройств (r6s, r5s, rb5009, slateax, ax59u, brume2) с выбранным вариантом. На slateax и ax59u в вариантах homeproxy, rehomeproxy, podkop, netshift, forkop и trafira всегда ставится sing-box-tiny из фида (выбор версии к ним не применяется, в матрице sb=tiny). С патчами homeproxy (004, 006) генератор сам подстраивается под версию из фида (1.13+). Без патчей (apply_patches = нет) сборка homeproxy с sing-box новее 1.12 остановится на проверке совместимости до компиляции — остальные при этом продолжатся; job setup предупреждает об этом заранее. Выбор, который вариант или устройство не допускают, setup приводит в соответствие и пишет об этом в лог (notice «Выбор скорректирован»).

02

Конвейер сборки

Что делает Universal_WRT_Builder.yml по шагам. Сначала job setup строит матрицу из выбранного target/variant, затем job build на раннере из поля runner_os прогоняет сборку для каждой пары «устройство × вариант», а job notify подводит итог.

  1. Матрица сборки. Из target/variant формируется список пар: combo → три фикс-сборки со своими настройками AGH/sing-box/youtubeUnblock/zz1, all → все шесть устройств, одиночный → одна пара.
  2. Подготовка раннера. Освобождение места на диске, checkout репозитория со скриптами.
  3. Права на files/. Делаются исполняемыми скрипты в files/etc/uci-defaults и files/usr/bin (попадут в образ).
  4. Скачивание AdGuardHome — только при agh = latest. Последний стабильный тег ищется через git ls-remote, архив сверяется по SHA-256 (sh/verify-sha256.sh: digest ассета из GitHub API, иначе checksums.txt релиза). При несовпадении бинарь не кладётся и используется пакет из фида. Бинарь кладётся в files/.
  5. Скачивание sing-box — только если в поле sb выбрана версия (не no, feed, tiny). Качается сборка -musl; бинарь под glibc в прошивку не кладётся. Тег выбирается через git ls-remote с сортировкой по версии; архив сверяется по SHA-256 (digest из GitHub API). Не скачалось или сумма не совпала — остаётся sing-box из фида.
  6. Переменные сборки. Вычисляются URL репозитория, ветка и коммит. Последний релизный тег ветки ищется через git ls-remote (сортировка по версии, без -rc); если тега нет или ручной коммит не релизный — используется <ветка>-SNAPSHOT. Подгружается конфиг устройства config/conf/<target>.
  7. Зависимости (apt). Установка тулчейна сборки из файла репозитория под выбранный раннер: depends-ubuntu-2404 или depends-ubuntu-2204.
  8. Клон исходников и checkout на нужный коммит/тег OpenWrt/ImmortalWrt.
  9. Патчи дерева. Файлы patches/*.patch (только корень каталога) применяются к исходникам OpenWrt: patch -p1 -d openwrt. Шаг идёт до feeds update, поэтому фидов здесь ещё нет; любой непримёнившийся патч останавливает сборку. Патчи к фидам лежат в подпапках patches/feeds/ и этим шагом не трогаются — см. следующий шаг.
  10. Update Feeds & Config. Главный шаг: P1 → фиды варианта и замена git.openwrt.org на GitHub → при feeds_latest коммиты фидов из репозитория пакетов (sh/feeds-from-repo.sh) → feeds update → P2 → feeds install → копирование WRT.config в .config (с удалением CRLF) → команды устройства → P3 → правки под вариант → отключение по Exclude-словам → make defconfig. Фид forkop выбирается полем Build Variant: forkop — оригинал ushan0v/forkop (FORKOP_FEED_ORIG) с патчами patches/feeds/forkop, forkop-mod — форк Gavr1024/forkop-mod (FORKOP_FEED_MOD) с патчем patches/feeds/forkopmod; адреса фидов — в env: workflow. Внутри сборки оба — вариант forkop. Применяется подпапка только загруженного фида, версия пакета берётся из его тегов. Вариант netshift подключает фид yandexru45/netshift (NETSHIFT_FEED) с патчами patches/feeds/netshift. Вариант trafira подключает свой фид petrouspetr-pixel/trafira (TRAFIRA_FEED) с патчами patches/feeds/trafira.
  11. part2Версии и патчи фидов. WRT-part2.sh (между feeds update и feeds install): берёт версию forkop и trafira из последнего тега x.y.z репозитория (FORKOP_VERSION / TRAFIRA_VERSION, без неё пакет получил бы 0.0.0) версию podkop (PODKOP_VERSION, без неё пакет получил бы 0.<дата>), версию netshift (NETSHIFT_VERSION) и версию темы Proton2025; версия берётся из репозитория, который подключён в feeds.conf. Затем применяет патчи из patches/feeds/<имя фида>/*.patch к feeds/<имя фида> по порядку имён: уже есть в исходниках — пропуск; не применён патч из строки Requires: — пропуск; иначе применяется только при точном совпадении контекста (patch -F 0), каждый целиком или никак. Не подошедшие — предупреждение в Actions и итог «применено / уже было / пропущено»; с FEED_PATCH_STRICT=1 сборка останавливается. Затем обновляется youtubeUnblock (кроме ytb = нет и вариантов clear, crystal_clear, switch, forkop, trafira — там его нет в прошивке).
  12. homeproxyПроверка совместимости sing-box. Генератор homeproxy, который попадёт в прошивку, проверяется против той версии sing-box, которая попадёт в прошивку (скачанной или из фида): пробный конфиг прогоняется через sing-box check. Несовместимость останавливает сборку до компиляции.
  13. Kernel Hash. Хеш ядра подменяется на официальный, чтобы на роутер можно было ставить готовые kmod из репозиториев.
  14. Компиляция. Многопоточная; при сбое — повтор в один поток с сохранением build.log.
  15. Bootloader-файлы. Глубокий поиск и сохранение idbloader.img/u-boot.itb/.fip для прошивки загрузчика.
  16. Артефакт. Содержимое bin/ загружается (upload-artifact@v7, хранение 10 дней) под именем <устройство>_<source>_<branch>_<вариант>_<patches|nopatches>_agh-<agh>_sb-<sb>_<ytb|noytb>_<zz|nozz>_<feeds-tag|feeds-repo>_<дата>, например nanopi-r6s_openwrt_openwrt-25.12_homeproxy_patches_agh-latest_sb-latest_ytb_zz_feeds-tag_2026.09.28-1200. Все параметры в имени различают сборки одного устройства и варианта; при падении компиляции туда же попадает build_failure.log.
  17. Уведомление (job notify). После всей матрицы в Telegram уходит одно сообщение со статусом и длительностью каждой сборки (если заданы секреты TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID); затем удаляются прогоны workflow старше 10 дней.
i

Где лежат патчи. patches/*.patch (только корень, подпапки не просматриваются) — к дереву OpenWrt (путь в патче от корня openwrt/). Все патчи отключаются полем apply_patches (в combo — полем patches матрицы). patches/feeds/forkop/ — 25 патчей к оригиналу ushan0v/forkop (по умолчанию), patches/feeds/forkopmod/ — к форку Gavr1024/forkop-mod 1.0.9 (вариант forkop-mod): вызовы ucode до объявления (без патча исключённые устройства идут через прокси) и prerm на sh для apk. patches/feeds/netshift/ — 2 патча к yandexru45/netshift (вариант netshift): разбор ссылок (socks5 с : в логине или пароле, транспорт http, совместимость с jq 1.7 на OpenWrt 24.10) и DNS (SRV/PTR/TXT мимо FakeIP, диагностика DNS-сервера с портом). patches/feeds/trafira/ — 3 патча к petrouspetr-pixel/trafira (вариант trafira): вызовы ucode до объявления в установщике компонентов, правило fw4 для TPROXY в образе прошивки и настройка «Исключить BitTorrent». patches/feeds/podkop/ — 5 патчей к itdoginfo/podkop (вариант podkop): разбор ссылок (пароли с %40/%23/+, IPv6, VLESS без type, httpupgrade, trojan с портом 443/; xhttp с 0.7.23 разбирает сам sing-box — нужно ядро podkop-engine), DNS (диагностика с портом, SRV/PTR мимо FakeIP), гонка start/reload, таймаут wget, проброс портов при Fully Routed IPs, настоящие IP для исключений, домены с заглавными и табуляцией, опция «Торренты мимо прокси». patches/feeds/luciappxray/ — 1 патч к yichya/luci-app-xray (вариант xray): адрес DNS без порта получает порт 53, а не 0 (иначе правила Fast/Secure DNS не срабатывали, а прямой DNS для имени сервера уходил в tproxy), FakeDNS без доменов не роняет генератор. patches/packages/luci-app-re-homeproxy/ — 3 патча Re:HomeProxy (запуск на обычном sing-box, несуществующий DNS-сервер по умолчанию, uTLS на QUIC-узлах и устаревшие поля подписок из ветки dev). patches/packages/luci-app-homeproxy/ — 6 патчей HomeProxy (проверка URLTest в LuCI, несуществующий DNS-сервер по умолчанию, права на логи в 25.12, поддержка sing-box 1.13+, исправления опечаток, опции кэша DNS для 1.14); применяются в WRT-part3.sh сразу после клонирования, на ImmortalWrt — к homeproxy из фида luci. Патч 005 в master homeproxy уже внесён автором (на OpenWrt — «уже есть»), а в фиде luci ImmortalWrt ещё нужен. В ветке dev автор сам перевёл генератор на правило sniff и убрал independent_cache: когда это попадёт в master, генератор станет совместим с sing-box 1.13+ без патчей, 004 станет лишним, а 002 и 006 придётся обновить (подробно — в patches/README.md). С патчем 004 проверка совместимости пропускает homeproxy с sing-box 1.13+. Имя подпапки должно совпадать с именем фида в feeds.conf. Подробности — в patches/README.md.

rehomeproxy (Re:HomeProxy): что важно знать. Форк homeproxy от 1andrevich (1andrevich/homeproxy-hiddify, пакет luci-app-re-homeproxy): ядро hiddify-core или sing-box-extended, встроенный обход DPI (ByeDPI и Zapret 2, nfqws2), правила маршрутизации для России, страница «Core & Tools» для установки ядер и компонентов. WRT-part3.sh клонирует ветку master в package/luci-app-re-homeproxy и ставит версию пакета как у сборок автора: <дата коммита>-r<число коммитов>. Пакет ставит файлы по тем же путям, что luci-app-homeproxy (/etc/config/homeproxy, /etc/init.d/homeproxy), поэтому homeproxy в этом варианте вырезается. Ядро — /usr/bin/sing-box из сборки (поле sb, рекомендуется extended); hiddify-core, ByeDPI и Zapret 2 приложение может доставить само на роутере. Модули kmod-nft-tproxy, kmod-tun, kmod-nft-queue уже в образе. zz1 настраивает его как homeproxy (dns_hijacked при AGH, DNS-порт 5333, обход по метке 0x64, YACD), а Clash API включает в существующем блоке форка. Без патча 001 форк на обычном sing-box (фид, 1.12.x…latest, tiny) не запускается ни в одном режиме — job setup предупреждает. Проверки совместимости sing-box, как у homeproxy, для него нет: генератор форка сам выбирает поля под ядро.

forkop: что важно знать. Пакеты forkop, luci-app-forkop, luci-i18n-forkop-ru в варианте forkop собираются из оригинала ushan0v/forkop 1.0.5 с 25 патчами (в варианте forkop-mod — из форка Gavr1024/forkop-mod с патчем 001: есть Xray и другие функции форка, но нет наших доработок ниже): 17 исправлений из открытых PR репозитория (авторы сохранены), исправления вызовов ucode до объявления, скрипта удаления для apk, совместимости с sing-box 1.14, зависания загрузки списков и показа доменов в LuCI, а также две настройки из forkop-mod в доработанном виде — «Исключить BitTorrent» и «Исключённые устройства» (по IP, подсети или MAC) — и настройка «Перехватывать DNS устройств». zz1-final-offline-setup.sh выключает её (intercept_device_dns=0, аналог dns_hijacked для homeproxy): DNS всех клиентов идёт через AdGuard Home, и он видит каждое устройство, а трафик исключённых устройств к FakeIP forkop отправляет напрямую. Для ядра sing-box в образ собирается пакет из фида (25.12: 1.13.x), а скачанный бинарь кладётся через files/ поверх него в /usr/bin/sing-box. Менеджер пакетов при этом считает установленной версию из фида, поэтому apk upgrade может вернуть её вместо extended — обновляйте sing-box через вкладку «Компоненты» forkop.

netshift: что важно знать. Пакеты netshift, luci-app-netshift, luci-i18n-netshift-ru собираются из yandexru45/netshift — активно развиваемого форка podkop (бета). Устроен как podkop: shell + jq, DNS sing-box на 127.0.0.42:53, youtubeUnblock совместим. Сверх podkop: несколько подписок в секции с фильтрами и группами по странам и автовыбором самого быстрого сервера, переключение ядра sing-box ↔ sing-box-extended (транспорт xhttp) прямо из LuCI, IPv6, блокировка DoH, «Торренты мимо прокси», EDNS Client Subnet, самообновление из LuCI. В 0.9.10 добавились вкладка «Устройства» (для каждого устройства: по спискам, напрямую или всё через секцию — без перехвата DNS, AGH по-прежнему видит всех), DNS-секции (свой DNS-сервер для доменов выбранных списков), пул DNS-серверов (резерв или параллельный опрос), каскад секций, приоритетный выбор сервера, фильтры подписки по стране, опция reality_mlkem и обход sing-box для исключённых адресов (bypass_excluded_ips, по умолчанию выключен; трафик на FakeIP-адреса всё равно идёт через sing-box). Конфиг — /etc/config/netshift (старый /etc/config/podkop переносится автоматически). Патчи patches/feeds/netshift: 001 — ссылки socks5 с : в логине или пароле давали нерабочий узел, ссылки VLESS/Trojan с транспортом http пропускались; на OpenWrt 24.10 (jq 1.7) не строились узлы с TLS/Reality и не работали подписки (на 25.12 с jq 1.8.1 этой проблемы нет); 002 — запросы SRV/PTR/TXT к доменам из списков оставались без ответа (FakeIP отвечает только на A/AAAA), диагностика считала недоступным DNS-сервер, заданный с портом. zz1-final-offline-setup.sh делает то же, что для podkop: AGH upstream 127.0.0.42:53, dont_touch_dhcp=1, exclude_ntp=1 и, раз youtubeUnblock в варианте есть, disable_quic=1. Домены, которые должны идти через youtubeUnblock (например googlevideo.com), добавляйте в секцию «Исключение»: netshift всё равно отдаёт им FakeIP, но направляет соединение напрямую, и оно проходит очередь youtubeUnblock уже от роутера. Самообновление netshift из LuCI ставит релиз автора поверх пакета из прошивки — патчи при этом теряются до следующей прошивки.

trafira: что важно знать. Пакеты trafira, luci-app-trafira, luci-i18n-trafira-ru собираются из petrouspetr-pixel/trafira — активно развиваемого продолжения forkop со своими тестами. В нём уже есть почти все исправления, которые для forkop дают наши патчи, а сверх них — Alice Mode (какие устройства идут через trafira, а какие мимо: по IP, MAC, интерфейсу, с настоящим DNS для обходящих), DoH с mTLS, Zapret/Zapret2/ByeDPI как действие секции, серверные inbound (VLESS Reality, MTProto, Tailscale). Xray, как в forkop-mod, нет. Конфиг — /etc/config/trafira, пакет конфликтует с forkop и podkop. Патчи patches/feeds/trafira: 001 — без него установка и обновление sing-box со вкладки «Компоненты» падают с ошибкой ucode; 002 — правило fw4, пропускающее TPROXY-трафик во input, ставится и в образе прошивки (/etc/uci-defaults/60_trafira-firewall, как патч 016 forkop), иначе гостевые зоны с input=REJECT режут проксируемый трафик; 003 — «Исключить BitTorrent» (как патч 023 forkop). Настройки «Исключённые устройства» и «Перехватывать DNS устройств» из наших патчей forkop здесь заменяет Alice Mode. zz1-final-offline-setup.sh делает для trafira то же, что для forkop: AGH upstream 127.0.0.42:53, dont_touch_dhcp=1, exclude_ntp=1. По умолчанию trafira DNS клиентов не перехватывает, и AGH видит каждое устройство. Если включить Alice Mode, DNS устройств «в обход» пойдёт в DNS trafira мимо AGH. youtubeUnblock в варианте нет (обход DPI — Zapret/ByeDPI самого trafira). sing-box — как у forkop: пакет из фида плюс скачанный бинарник при выборе версии в sb; обновлять его лучше со вкладки «Компоненты».

Рейтинг вариантов для NanoPi R6S

Оценка для R6S в роли главного роутера с AdGuard Home на :53 и youtubeUnblock. Критерии: надёжность связки с AGH, сколько патчей нужно и живо ли развитие у автора, удобство настройки. Это экспертная оценка по коду и патчам, а не результат замеров. Во всех прокси-вариантах есть zz1, TCP BBR и AdGuard Home (dnsmasq переезжает на :54) и нет SQM — в таблице только различия.

04

Первый старт после прошивки

Скрипт zz1-final-offline-setup.sh лежит в /etc/uci-defaults/ и выполняется при первой загрузке роутера (режим firstboot, лог /root/setup_log.txt). Сохранённую копию можно запустить вручную, например после apk upgrade (режим maintenance, лог /root/setup_log_maintenance.txt): тогда hostname, customfeeds и настройки first boot не трогаются — подробно в подразделе «Режимы firstboot и maintenance». Многие шаги выполняются с учётом выбранного варианта. Скрипта нет в варианте crystal_clear и в любой сборке с полем zz = нет — тогда раздел к ней не относится. Полный список изменений — в files/README.md.

  1. Инициализация. Логирование, определение версии ядра, архитектуры, модели роутера и текущего варианта сборки.
  2. База. Часовой пояс (Europe/Moscow), очистка строки FullCone, сохранение system.
  3. Пакетный менеджер. Определение apk/opkg, чистка репозиториев, добавление репозитория kmods (по версии ядра), customfeeds; ключи /root/apps/*.pem ставятся в /etc/apk/keys/.
  4. Локальные бинари. sing-box, AdGuardHome и speedtest из /root/apps/ ставятся в /usr/bin.
  5. homeproxy (если установлен): форсится dns_hijacked=1, создаётся firewall-хелпер, патчится init, добавляется bypass-чейн nftables; Clash API на :9090 и панель YACD (догружается cron-ом, пункт меню в LuCI). Без homeproxy — удаляются его nft-файл и include-секции firewall.
  6. Наборы адресов fw4. Всегда создаются ipset dpi_ips, bypass_ips, bypass_local (с loadfile в /etc/luci-uploads/).
  7. Прокси под вариант. passwall2 — базовые настройки на first boot; xray — на first boot заводские «китайские» правила luci-app-xray меняются на русские (напрямую GeoIP ru и geosite:category-ru, Fast DNS 77.88.8.8), если их не меняли вручную; forkop, trafira, podkop и netshift — exclude_ntp=1 (NTP мимо прокси), а при установленном youtubeUnblock ещё disable_quic=1 (QUIC к адресам FakeIP отклоняется в sing-box, браузер идёт по TCP, который обрабатывает youtubeUnblock). xray и v2rayA не настраиваются.
  8. youtubeUnblock. Запись правил nftables с ipset-байпасами, очередь 537, метка гостевой сети; START=99.
  9. internet-detector / owut. internet-detector выключается (чтобы не висел службой, а активировался при открытии страницы luci), owut настраивается.
  10. AdGuardHome. dnsmasq переезжает на порт 54, AGH занимает 53; upstream DNS — sing-box homeproxy (127.0.0.1:5333), DNS Xray для варианта xray (127.0.0.1:5300) или forkop/trafira/podkop/netshift (127.0.0.42:53, плюс dont_touch_dhcp=1; у forkop ещё intercept_device_dns=0); создаётся LuCI-редирект на :8080, служба запускается.
  11. SQM и BBR. Если SQM установлен — настраивается CAKE; TCP BBR включается, если модуль есть в ядре.
  12. FullCone NAT — только на ImmortalWrt и только при наличии модуля (на OpenWrt тихо пропускается).
  13. Время и идентичность. Синхронизация RTC/NTP, исправление mtime из будущего, обновление баннера; hostname и commonname — только на first boot.
  14. switchРежим L2-коммутатора. Только для switch: все порты собираются в br-lan, DHCP-клиент, firewall-зоны и WAN отключаются.
  15. Перезагрузка. Отложенный ребут через 120 секунд в фоне — чтобы применить sysctl, AGH и остальное.

Режимы firstboot и maintenance

Режим определяется одним файлом-признаком /etc/zz1_setup_completed: его нет — firstboot, он есть — maintenance. Скрипт создаёт его в самом конце в обоих режимах. Файл лежит в /etc, а не в /root: /root часто целиком вписан в /etc/sysupgrade.conf, исключений этот файл не поддерживает, и признак переживал бы прошивку. В бэкап и при прошивке с сохранением настроек он не попадает. Старый признак /root/.setup_completed скрипт удаляет.

СитуацияРежимПочему
Прошивка без сохранения настроекfirstboot

Чистая система, признака нет.

Прошивка с сохранением настроекfirstboot

Признак в /etc не сохраняется. Старые конфиги возвращаются до запуска zz1, и он работает поверх них.

Чистая прошивка + «Восстановить» из бэкапаfirstboot, затем бэкап

zz1 отрабатывает на чистых конфигах, потом бэкап их перезаписывает (hostname и customfeeds вернутся свои). После смены варианта так делать нельзя: вернутся настройки AGH и прочее от старого варианта.

Ручной запуск копии скрипта (например, после apk upgrade)maintenance

Признак уже создан прошлым запуском на этой прошивке.

Что отличается. От режима зависят только эти пять мест — всё остальное выполняется одинаково:

Что одинаково в обоих режимах. Эти шаги можно повторять: они проверяют, сделано ли уже, или приводят состояние к нужному.

  • Система: часовой пояс; строка FullCone удаляется (и fullcone=1 возвращается, если модуль есть в ядре); TCP BBR в sysctl.conf.
  • Пакетный менеджер: архитектура apk, очистка distfeeds.list от лишних фидов, строка kmods под текущее ядро (копия distfeeds.list.bak делается один раз); ключи /root/apps/*.pem.
  • Локальные бинарники: sing-box, AdGuardHome, speedtest из /root/apps.
  • homeproxy: dns_hijacked (при AGH), Clash API и YACD (заглушка — только если панели ещё нет), правка init, bypass_homeproxy_ips.nft. Без homeproxy — удаление его хвостов.
  • Firewall: наборы dpi_ips, bypass_ips, bypass_local (создаются, если их нет), правка ruleset.uc для flow offload.
  • youtubeUnblock: правила nft очереди 537 (или их удаление, если пакета нет).
  • AdGuard Home: рабочий каталог, dnsmasq на порт 54, upstream под вариант (127.0.0.1:5333, 127.0.0.1:5300 у xray или 127.0.0.42:53 + dont_touch_dhcp=1); exclude_ntp=1 для forkop, trafira, podkop, netshift; там же при youtubeUnblock — disable_quic=1.
  • SQM: патч run.sh; свой /opt/sqm_custom.conf не перезаписывается.
  • Прочее: internet-detector, owut, phy-leds; свои контроллеры LuCI из /root/apps/luci-controllers (уже существующие не затираются); меню файлового менеджера; время и RTC, mtime из будущего; строки баннера.
  • В конце: создаётся /etc/zz1_setup_completed, через 120 секунд перезагрузка.

Коротко: maintenance = firstboot без перезаписи customfeeds.list, hostname и commonname и без первичной настройки passwall2 и режима коммутатора. После прошивки с сохранением настроек zz1 идёт как firstboot: переименованный роутер снова получит имя по шаблону, а свои фиды в customfeeds.list придётся вписать заново.

Вариант forkop: цепочка DNS

Клиенты LANDNS → роутер→ AdGuardHome:53→ sing-box forkop127.0.0.42:53→ FakeIP / upstreamпо правилам секций

forkop

LuCI → Services → Forkop

Панель, секции, «Компоненты» (sing-box / Xray). dont_touch_dhcp=1: dnsmasq не перенастраивается, DNS держит AGH. intercept_device_dns=0: DNS не перехватывается ни для одного устройства.

dnsmasq

:54 · dnsmasq-full

DHCP и локальные имена; -full нужен для nftset в режиме Xray.

NTP мимо прокси

exclude_ntp=1

Правило udp dport 123 return для клиентов и самого роутера.

Проверка после прошивки

ssh

sing-box version и logread | grep forkop — без «left-hand side is not a function».

i

DNS-запросы всех клиентов идут сначала в AdGuardHome, и он видит каждое устройство: журнал, статистика и правила по клиентам работают. В forkop запросы приходят уже от AdGuardHome, с адреса самого роутера. Поэтому устройства из «Исключённых устройств» и секций с фильтром по устройству forkop различает не по DNS, а по трафику. Исключённые устройства тоже получают FakeIP для доменов из списков, но такие соединения forkop отправляет напрямую, мимо прокси. Перехват DNS по устройствам остаётся только для DNS-секций с фильтром по устройству: там forkop отвечает сам, минуя AdGuardHome.
