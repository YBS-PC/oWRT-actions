Справочник прошивки

Universal WRT Builder

Конвейер GitHub Actions, который собирает прошивку OpenWrt / ImmortalWrt под несколько устройств в выбранном «варианте» начинки, и скрипт zz1-final-offline-setup.sh, который доводит роутер до рабочего состояния на первом старте. Эта страница объясняет, что задаётся при запуске, что происходит во время сборки, чем отличаются варианты и что получается после прошивки.

02

Конвейер сборки

Что делает Universal_WRT_Builder.yml по шагам. Сначала job setup строит матрицу из выбранного target/variant, затем job build на раннере из поля runner_os прогоняет сборку для каждой пары «устройство × вариант», а job notify подводит итог.

  1. Матрица сборки. Из target/variant формируется список пар: combo → четыре фикс-сборки со своими настройками AGH/sing-box, all → все шесть устройств, одиночный → одна пара.
  2. Подготовка раннера. Освобождение места на диске, checkout репозитория со скриптами.
  3. Права на files/. Делаются исполняемыми скрипты в files/etc/uci-defaults и files/usr/bin (попадут в образ).
  4. Скачивание AdGuardHome — если включён флаг и вариант это допускает. Последний стабильный тег ищется через git ls-remote, архив сверяется по SHA-256 (sh/verify-sha256.sh: digest ассета из GitHub API, иначе checksums.txt релиза). При несовпадении бинарь не кладётся и используется пакет из фида. Бинарь кладётся в files/.
  5. Скачивание sing-box — если выбрано не no и вариант это допускает. Тег выбирается через git ls-remote с сортировкой по версии; архив сверяется по SHA-256 (digest из GitHub API). Не скачалось или сумма не совпала — остаётся sing-box из фида.
  6. Переменные сборки. Вычисляются URL репозитория, ветка и коммит. Последний релизный тег ветки ищется через git ls-remote (сортировка по версии, без -rc); если тега нет или ручной коммит не релизный — используется <ветка>-SNAPSHOT. Подгружается конфиг устройства config/conf/<target>.
  7. Зависимости (apt). Установка тулчейна сборки из файла репозитория под выбранный раннер: depends-ubuntu-2404 или depends-ubuntu-2204.
  8. Клон исходников и checkout на нужный коммит/тег OpenWrt/ImmortalWrt.
  9. Патчи дерева. Файлы patches/*.patch (только корень каталога) применяются к исходникам OpenWrt: patch -p1 -d openwrt. Шаг идёт до feeds update, поэтому фидов здесь ещё нет; любой непримёнившийся патч останавливает сборку. Патчи к фидам лежат в подпапках patches/feeds/ и этим шагом не трогаются — см. следующий шаг.
  10. Update Feeds & Config. Главный шаг: P1 → feeds update → P2 → feeds install → копирование WRT.config в .config (с удалением CRLF) → команды устройства → P3 → правки под вариант → отключение по Exclude-словам → make defconfig. Для варианта forkop фид выбирается сам: если в patches/feeds/forkop есть патчи — оригинал ushan0v/forkop (фид forkop) с этими патчами, если патчей нет — форк Gavr1024/forkop-mod (фид forkopmod), как раньше.
  11. part2Версии и патчи фидов. WRT-part2.sh (между feeds update и feeds install): берёт версию forkop из последнего тега x.y.z репозитория (FORKOP_VERSION, без неё пакет получил бы 0.0.0) и версию темы Proton2025; версия берётся из репозитория, который подключён в feeds.conf. Затем применяет патчи из patches/feeds/<имя фида>/*.patch к feeds/<имя фида> по порядку имён: уже есть в исходниках — пропуск; не применён патч из строки Requires: — пропуск; иначе применяется только при точном совпадении контекста (patch -F 0), каждый целиком или никак. Не подошедшие — предупреждение в Actions и итог «применено / уже было / пропущено»; с FEED_PATCH_STRICT=1 сборка останавливается. Затем обновляется youtubeUnblock (кроме clear/switch/forkop).
  12. homeproxyПроверка совместимости sing-box. Генератор homeproxy, который попадёт в прошивку, проверяется против той версии sing-box, которая попадёт в прошивку (скачанной или из фида): пробный конфиг прогоняется через sing-box check. Несовместимость останавливает сборку до компиляции.
  13. Kernel Hash. Хеш ядра подменяется на официальный, чтобы на роутер можно было ставить готовые kmod из репозиториев.
  14. Компиляция. Многопоточная; при сбое — повтор в один поток с сохранением build.log.
  15. Bootloader-файлы. Глубокий поиск и сохранение idbloader.img/u-boot.itb/.fip для прошивки загрузчика.
  16. Артефакт. Содержимое bin/ загружается (upload-artifact@v7, хранение 10 дней); при падении компиляции туда же попадает build_failure.log.
  17. Уведомление (job notify). После всей матрицы в Telegram уходит одно сообщение со статусом и длительностью каждой сборки (если заданы секреты TELEGRAM_BOT_TOKEN/TELEGRAM_CHAT_ID); затем удаляются прогоны workflow старше 10 дней.
i

Где лежат патчи. patches/*.patch — к дереву OpenWrt (путь в патче от корня openwrt/). patches/feeds/forkop/ — 25 патчей к оригиналу ushan0v/forkop (используется сейчас), patches/feeds/forkopmod/ — к форку Gavr1024/forkop-mod (если переключить фид в YML). patches/packages/luci-app-homeproxy/ — 5 патчей HomeProxy (проверка URLTest в LuCI, несуществующий DNS-сервер по умолчанию, права на логи в 25.12, поддержка sing-box 1.13+, исправления из ветки dev); применяются в WRT-part3.sh сразу после клонирования. С патчем 004 проверка совместимости пропускает homeproxy с sing-box 1.13+. Имя подпапки должно совпадать с именем фида в feeds.conf. Подробности — в patches/README.md.

Различие clear и crystal_clear: crystal_clear вдобавок удаляет сам zz1 — это «чистая болванка» без первичной настройки. switch делит bloat-список с crystal_clear, но оставляет zz1, который переводит устройство в L2-мост.

◆

forkop: что важно знать. Пакеты forkop, luci-app-forkop, luci-i18n-forkop-ru собираются из оригинала ushan0v/forkop 1.0.5 с 25 патчами: 17 исправлений из открытых PR репозитория (авторы сохранены), исправления вызовов ucode до объявления, скрипта удаления для apk, совместимости с sing-box 1.14, зависания загрузки списков и показа доменов в LuCI, а также две настройки из forkop-mod в доработанном виде — «Исключить BitTorrent» и «Исключённые устройства» (по IP, подсети или MAC) — и настройка «Перехватывать DNS устройств». zz1-final-offline-setup.sh выключает её (intercept_device_dns=0, аналог dns_hijacked для homeproxy): DNS всех клиентов идёт через AdGuard Home, и он видит каждое устройство, а трафик исключённых устройств к FakeIP forkop отправляет напрямую. Для ядра sing-box в образ собирается пакет из фида (25.12: 1.13.x), а скачанный бинарь (в combo — extended 1.14.x) кладётся через files/ поверх него в /usr/bin/sing-box. Менеджер пакетов при этом считает установленной версию из фида, поэтому apk upgrade может вернуть её вместо extended — обновляйте sing-box через вкладку «Компоненты» forkop.

04

Первый старт после прошивки

Скрипт zz1-final-offline-setup.sh лежит в /etc/uci-defaults/ и выполняется при первой загрузке роутера (режим firstboot, лог /root/setup_log.txt). Сохранённую копию можно запустить вручную, например после apk upgrade (режим maintenance, лог /root/setup_log_maintenance.txt): тогда hostname, customfeeds и настройки first boot не трогаются. Многие шаги выполняются с учётом выбранного варианта. Полный список изменений — в files/README.md.

  1. Инициализация. Логирование, определение версии ядра, архитектуры, модели роутера и текущего варианта сборки.
  2. База. Часовой пояс (Europe/Moscow), очистка строки FullCone, сохранение system.
  3. Пакетный менеджер. Определение apk/opkg, чистка репозиториев, добавление репозитория kmods (по версии ядра), customfeeds; ключи /root/apps/*.pem ставятся в /etc/apk/keys/.
  4. Локальные бинари. sing-box, AdGuardHome и speedtest из /root/apps/ ставятся в /usr/bin.
  5. homeproxy (если установлен): форсится dns_hijacked=1, создаётся firewall-хелпер, патчится init, добавляется bypass-чейн nftables; Clash API на :9090 и панель YACD (догружается cron-ом, пункт меню в LuCI). Без homeproxy — удаляются его nft-файл и include-секции firewall.
  6. Наборы адресов fw4. Всегда создаются ipset dpi_ips, bypass_ips, bypass_local (с loadfile в /etc/luci-uploads/).
  7. Прокси под вариант. passwall2 — базовые настройки на first boot; forkop — exclude_ntp=1 (NTP мимо прокси). xray, v2rayA и podkop не настраиваются.
  8. youtubeUnblock. Запись правил nftables с ipset-байпасами, очередь 537, метка гостевой сети; START=99.
  9. internet-detector / owut. internet-detector выключается (чтобы не висел службой, а активировался при открытии страницы luci), owut настраивается.
  10. AdGuardHome. dnsmasq переезжает на порт 54, AGH занимает 53; upstream DNS — sing-box homeproxy (127.0.0.1:5333) или forkop (127.0.0.42:53, плюс dont_touch_dhcp=1 и intercept_device_dns=0); создаётся LuCI-редирект на :8080, служба запускается.
  11. SQM и BBR. Если SQM установлен — настраивается CAKE; TCP BBR включается, если модуль есть в ядре.
  12. FullCone NAT — только на ImmortalWrt и только при наличии модуля (на OpenWrt тихо пропускается).
  13. Время и идентичность. Синхронизация RTC/NTP, исправление mtime из будущего, обновление баннера; hostname и commonname — только на first boot.
  14. switchРежим L2-коммутатора. Только для switch: все порты собираются в br-lan, DHCP-клиент, firewall-зоны и WAN отключаются.
  15. Перезагрузка. Отложенный ребут через 120 секунд в фоне — чтобы применить sysctl, AGH и остальное.

DNS-запросы всех клиентов идут сначала в AdGuardHome, и он видит каждое устройство: журнал, статистика и правила по клиентам работают. В forkop запросы приходят уже от AdGuardHome, с адреса самого роутера. Поэтому устройства из «Исключённых устройств» и секций с фильтром по устройству forkop различает не по DNS, а по трафику. Исключённые устройства тоже получают FakeIP для доменов из списков, но такие соединения forkop отправляет напрямую, мимо прокси. Перехват DNS по устройствам остаётся только для DNS-секций с фильтром по устройству: там forkop отвечает сам, минуя AdGuardHome.

Справочник составлен по файлам проекта Universal_WRT_Builder.yml, WRT-part1..3.sh, verify-sha256.sh и zz1-final-offline-setup.sh; подробный список изменений первого старта — в files/README.md, устройство каталога патчей — в patches/README.md. Матрица вариантов отражает логику сборки; крайние случаи (например, SQM на clear) стоит сверять с WRT.config, если они критичны.
