# CLAUDE.md

Инструкции для Claude Code в этом репозитории.

Репозиторий — личные настройки сборки прошивок OpenWrt / ImmortalWrt
для тестируемых устройств через GitHub Actions. Это не продукт и не проект
для других людей (см. предупреждение в `README.md`). Репозиторий
**публичный**: всё.

## Главные правила

### 1. В репозиторий ничего не записывать самому

- Не делать коммиты, push, ветки, PR, issue, комментарии и релизы.
  Не запускать и не отменять workflow. Исключение — прямая просьба
  автора в текущем разговоре, и только на то, о чём просили.
- Изменённые файлы класть в scratchpad **целиком**, с тем же путём, что
  в репозитории (`files/etc/uci-defaults/...`, `.github/workflows/...`),
  и отдавать автору. Он сам загружает их через веб-интерфейс GitHub.
- Перед работой сверять локальную копию с `origin/main`: автор мог
  загрузить файлы после прошлой сессии.

### 2. Никаких личных и служебных данных

Ни в файлах, ни в патчах, ни в комментариях, ни в выводе workflow не
должно быть:

- адресов, доменов, портов и путей серверов и панелей управления;
- ключей, паролей, UUID, токенов, ссылок-подписок, идентификаторов
  DNS-сервисов, логинов провайдера;
- плана адресации домашней сети, MAC-адресов, имён устройств и людей;
- содержимого конфигов, логов, отчётов и архивов, которые автор
  присылает в чат.

Всё это нужно только для ответа в чате. В репозиторий и в документы
для него это не переносить, даже в примерах (за исключением общеизвестных данных необходимых для правильной работы): в примерах писать
`<адрес>`, `192.0.2.1`, `example.com`.

Логи Actions и артефакты публичного репозитория доступны всем.
Поэтому:
- не выводить секреты и личные данные через `echo`, `cat`, `set -x` и в
  Job Summary;
- не класть в `files/` ничего личного: эта папка целиком попадает в образ
  прошивки.

Секреты workflow: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и
`GITHUB_TOKEN`. Используются только через `secrets.*`.

### 3. Нейтральный технический язык

Нельзя рекламировать или рекомендовать
способы обхода ограничений и блокировок и подсказывать, как это делать.
Поэтому во всём, что попадает в репозиторий (README, справочники,
комментарии, описания патчей и полей формы, сообщения коммитов, тексты
уведомлений), правила такие:

- Описывать, **что делает код технически**: исправляет ошибку, даёт
  совместимость с apk / fw4 / rpcd / новой версией зависимости,
  добавляет опцию (по умолчанию выключена или повторяет прежнее
  поведение).
- Не писать, **для чего** пакет можно применять. Не сравнивать пакеты и
  способы по этому признаку, не давать советов и инструкций. Не называть
  ресурсы, сервисы или страны, к которым что-то относится.
- Не добавлять списки доменов, адресов и ресурсов, серверы, подписки и
  готовые конфигурации. Патчи не меняют назначение пакетов: см.
  `patches/README.md`.
- Не делать репозиторий привлекательным для других: никаких инструкций
  по установке и прошивке для посторонних, бейджей, релизов, лицензии и
  ссылок «скачать сборку».
- Предупреждение в начале `README.md` не смягчать, не сокращать и не
  убирать.
- Сторонние пакеты называть их собственными именами, как в фидах, со
  ссылкой на автора. Их описание не пересказывать.

Если просьба автора требует нарушить эти правила в репозитории, предупредить
об этом и предложить вариант, который остаётся только в чате или в
локальном файле автора.

## Устройство репозитория

| Путь | Что это |
|---|---|
| `.github/workflows/Universal_WRT_Builder.yml` | сборка: job `setup` (матрица), `build`, `notify` (итог в Telegram) |
| `.github/workflows/Cleanup.yml` | удаление старых запусков и артефактов |
| `sh/WRT-part1.sh` … `part3.sh` | шаги сборки: подготовка, фиды и `.config`, сторонние пакеты и патчи |
| `sh/feeds-from-repo.sh`, `patch-drift.sh`, `verify-sha256.sh` | фиды, сверка патчей с исходниками, проверка загрузок |
| `config/WRT.config`, `config/conf/<устройство>` | общий и посекционный `.config`; правила записи — `config/config_rules.txt` |
| `patches/` | исправления и улучшения сторонних пакетов; как применяются — `patches/README.md` |
| `files/` | копируется в корень образа (кроме `README.md`) |
| `files/etc/uci-defaults/zz1-final-offline-setup.sh` | настройка при первой загрузке; справочник — `files/README.md` |
| `files/usr/lib/sqm/cake_ctinfo.qos` | скрипт SQM |
| `docs/` | справочник по сборке (`wrt-builder-reference.html`, GitHub Pages) и схемы устройств |

Поля формы workflow: `target`, `variant`, `source`, `branch`, `agh`,
`sb`, `ytb`, `zz`, `apply_patches`, `use_base_commit`,
`stop_outdated_patches`, `feeds_latest`, `exclude_keywords`,
`commit_hash`, `runner_os`. В режиме `combo` поля со звёздочкой берутся
из строк матрицы в job `setup`.

## Технические особенности

- **OpenWrt 25.12:** пакеты apk (не opkg), firewall fw4 / nftables,
  LuCI на ucode. Lua-страницы LuCI работают через `luci-compat` и
  `luci-lua-runtime`.
- **Скрипты на роутере** (`files/etc/uci-defaults/*`) — `#!/bin/sh`, то
  есть busybox ash. Нужен POSIX sh без bash-конструкций. В busybox
  OpenWrt нет дробного `sleep` и `sort -h`. GNU-утилиты (coreutils,
  gawk) есть не на всех устройствах: проверять через `command -v`.
- **Скрипты сборки** (`sh/*.sh`) — bash, выполняются на раннере Ubuntu.
- **zz1:** режимы `firstboot` и `maintenance`, lock
  `/etc/zz1_setup_completed`, в конце перезагрузка через 120 секунд.
  Повторный запуск не должен ничего ломать (идемпотентность). Ветки по
  варианту сборки и по наличию пакетов — внутри скрипта.
- **Патчи:** серия снимается по очереди с состояния после предыдущего
  патча. Строка `index` в diff обязательна, по ней `patch-drift.sh`
  сверяет код. Первая строка `BASE` — коммит автора пакета, на который
  сняты патчи; при перевыпуске серии обновлять `BASE`. Пропуски в
  нумерации допустимы. Патч для части сборок — заголовок `Build-If:`.
- **Notify:** API `jobs` отдаёт `conclusion` и `completed_at` с
  задержкой. Код ждёт их и подставляет `needs.build.result`, если их
  нет. Это поведение не ломать.

## Проверки перед тем, как отдать файл

- `sh -n` для `files/etc/uci-defaults/*`, `bash -n` для `sh/*.sh`;
  `shellcheck`, если установлен (для uci-defaults — `-s sh`).
- Workflow: разбор YAML (`python3 -c 'import yaml,sys; yaml.safe_load(open(sys.argv[1]))'`),
  `actionlint`, если установлен.
- Патч: `git apply --check` на исходниках с коммита из `BASE`.
- Перечитать изменённые строки на соответствие правилам 2 и 3.
- Изменение держать минимальным, стиль и язык комментариев — как в
  соседнем коде (по-русски). `README.md` в корне — по-английски.
